# 🔄 Руководство по переиндексации

> После обновления схемы полей `name_ru` и `name_en` необходимо один раз вручную
> запустить полную переиндексацию. Существующий индекс не получает новые
> `keyword`-подполя и normalizer автоматически.

## Способы принудительной переиндексации

### 1. Через параметр командной строки `--reindex` ⭐ (Рекомендуется)

**Windows (bat):**
```cmd
start_mcp_server.bat --reindex
```

**Windows (PowerShell):**
```powershell
.\start_mcp_server.ps1 --reindex
```

**Прямой запуск:**
```bash
python -m uvicorn src.main:app --host 0.0.0.0 --port 8000 --reindex
```

**Что происходит:**
- ✅ Сервер запускается
- ✅ Через 5 секунд начинается фоновая переиндексация
- ✅ Старый индекс удаляется
- ✅ Все документы индексируются заново (~5500 документов)
- ⏱️ Время: 3-5 минут

---

### 2. Через переменную окружения `REINDEX_ON_STARTUP`

**В файле `.env`:**
```properties
REINDEX_ON_STARTUP=true
```

Затем запустите сервер обычным способом:
```cmd
start_mcp_server.bat
```

**Важно:** После переиндексации верните значение в `false`, иначе переиндексация будет происходить при каждом запуске!

---

### 3. Через API endpoint (после запуска сервера)

**PowerShell:**
```powershell
Invoke-RestMethod -Uri "http://localhost:8000/index/rebuild" -Method POST
```

**curl:**
```bash
curl -X POST http://localhost:8000/index/rebuild
```

**Особенности:**
- ⚠️ Индексация **синхронная** - запрос ждёт завершения
- ⏱️ Таймаут может сработать, если индексация долгая
- ✅ Возвращает результат с количеством документов

---

### 4. Удаление индекса вручную

**Удалить индекс через Elasticsearch API:**
```powershell
Invoke-RestMethod -Uri "http://192.168.0.18:9200/help1c_docs" -Method DELETE
```

Затем перезапустите сервер - произойдёт автоматическая индексация.

## Проверка статуса индексации

### Через API:

```powershell
# Краткий статус
Invoke-RestMethod -Uri "http://localhost:8000/health"

# Подробный статус индексации
Invoke-RestMethod -Uri "http://localhost:8000/index/status"
```

### Ответ:
```json
{
  "indexing": {
    "is_active": true,
    "status": "in_progress",

    "indexed_documents": 2500,
    "total_documents": 5500,

    "duration_seconds": 125.5
  }
}
```

## Приоритеты

Если задано несколько способов одновременно:

1. **Параметр `--reindex`** (высший приоритет)
2. **Переменная `REINDEX_ON_STARTUP=true`**
3. **Автоматическая индексация** (только если индекс пуст)

---

## Примеры использования

### Первый запуск (база пустая):
```cmd
start_mcp_server.bat
```
→ Автоматически проиндексирует

### Обновление документации:
```cmd
start_mcp_server.bat --reindex
```
→ Принудительно переиндексирует

### Регулярная переиндексация:
В `.env`:
```properties
REINDEX_ON_STARTUP=true
```
→ Каждый запуск переиндексирует (осторожно!)

### Переиндексация работающего сервера:
```powershell
Invoke-RestMethod -Uri "http://localhost:8000/index/rebuild" -Method POST
```
→ Переиндексирует без перезапуска
